Agent Project Seed v1.0

把任意仓库变成 AI 编程 Agent 的纪律化工作空间。

Agent Project Seed 是一个复制即用、零依赖的项目底座，面向在同一项目中使用 Codex、Claude Code、Gemini CLI 或多种 AI Agent 的团队和个人。它不是 Agent 框架，而是给你的仓库加上一层不可或缺的协调层：共享规则、当前状态、结构化账本、健康检查、安全提交，以及为不同 Agent 工具同步生成的入口文件。

大多数 AI Agent 配置止步于一个指令文件。这个项目再深一层。

  • 所有 Agent 共享一份合约
  • 一份当前状态快照用于交接
  • 一份结构化账本记录决策、风险、问题、会话和产物
  • 安全提交工具拒绝密钥、临时输出和意外路径
  • 同步生成 AGENTS.md、CLAUDE.md、GEMINI.md 入口
  • Python >= 3.9，无运行时依赖

为什么做这个

AI 编程工具在孤立任务上已经越来越好，但当每次会话从不同的记忆、提示词或工具专属惯例开始时，项目仍然会跑偏。

Agent Project Seed 适用于你产生这些念头的时刻：

  • 我反复向每个 Agent 解释同样的项目规则。
  • Claude、Codex 和 Gemini 应该读同一份真相源。
  • 我想要轻量的项目记忆，不想引入重型工作流系统。
  • 我需要 Agent 留下有用的记录，而不是聊天流水。
  • 我想在 Agent 提交改动前有自动护栏。

Quick Start

Clone 或复制本仓库，然后初始化：

python3 tools/project.py init --name "你的项目名"

填写项目意图：

$EDITOR control/contract.md

运行项目检查：

python3 tools/project.py check

如果修改了共享规则，重新生成 Agent 入口文件：

python3 tools/project.py sync-agents

工作原理

脚手架将协调层与项目工作分离。

层文件用途
治理control/contract.md共享规则、项目目标、非目标、验收标准
交接control/state.md简短的当前状态快照，供下一个 Agent 或会话使用
记忆control/ledger.md请求、决策、会话、风险、问题、产物的结构化记录
工作区work/in、work/out、work/tmp输入材料、正式产物、临时文件
工具tools/project.py、tools/panel.py初始化、检查、同步、安全提交、状态面板生成
Agent 入口AGENTS.md、CLAUDE.md、GEMINI.md各工具专属文件，统一指向共享合约

你会得到什么

功能说明
共享合约control/contract.md 是协作规则的唯一真相源。
统一账本需求、决策、风险、问题、会话和产物使用相同的可读记录格式。
当前状态control/state.md 保持交接简短、具体、易于更新。
安全提交project.py commit 只暂存白名单路径，拒绝 .env、临时文件、生成产物、冲突和意外路径。
健康检查project.py check 验证必需文件、Agent 同步、包导入、Claude hook 文件、gitkeep 文件和平台垃圾文件。
Agent 同步project.py sync-agents 从共享合约重新生成 AGENTS.md、CLAUDE.md、GEMINI.md。
状态面板tools/panel.py 报告项目状态、账本数量、git 状态、包名、目标和下一步。
Claude Hooks示例 Claude Code hook 可注入状态面板并运行安全存档。
工具包src/base_scaffold/ 包含路径辅助、原子写入、环境变量加载、API 门控、Record/Ledger/Manifest/QC 和 Review 页面工具。

有什么不同

Agent Project Seed 刻意保持小巧。它不试图编排 Agent、替代你的 Issue 跑后台群集、或发明新的项目管理宗教。

命令

# 验证脚手架
python3 tools/project.py check

# 复制后初始化
python3 tools/project.py init --name "你的项目名"

# 重新生成 AGENTS.md、CLAUDE.md、GEMINI.md
python3 tools/project.py sync-agents

# 只提交安全的白名单改动
python3 tools/project.py commit --message "chore: checkpoint agent work"

# 运行测试
python3 -m pytest

同样可以通过 make 使用：

make preflight
make test
make sync-agents

适合什么

适合

  • 多个 AI 编程工具协作的仓库
  • 长期运行的个人项目，Agent 记忆很重要
  • 想要轻量规则再逐步引入更重流程的团队
  • 内容、数据、研究、自动化和软件项目中可复用的交接
  • 生成产物、临时文件和密钥必须远离提交的项目

不适合

  • 只需要一个静态提示词文件
  • 想要托管仪表盘或 SaaS 工作流
  • 需要自主 Agent 调度或任务执行
  • 想完全替代 GitHub Issues、Linear、Jira 等 PM 工具

设计原则

真相源保持纯文本。
记录对未来的 Agent 有用，不为冗长而冗长。
偏好小巧可检查的脚本，不引入框架锁定。
默认守护提交安全。
项目结构只在工作真正需要时才生长。
