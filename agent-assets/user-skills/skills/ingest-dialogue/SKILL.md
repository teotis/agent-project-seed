# Ingest Dialogue

长期保存对话材料，按照 ThoughtCodex 最小更新面策略生成原始证据层 + 正式条目 + 必要观点卡。

## 规则

- 原始问题优先：保存用户原句，不润色、不概括
- 用户判断优先：严格区分用户判断与 AI 分析
- 最小更新面：默认只做原始证据 + 正式条目 + 必要观点卡；其余索引按需更新
- 不删除原始记录，不掩盖矛盾、犹豫和不确定

## 工作流

### Step 1: 判断材料价值

确认材料是否值得长期保存。检查是否包含：
- 用户提出的高价值原始问题
- 用户明确表达、认可、修正或采纳的判断
- 观点变化（强化/修正/反驳/扩展/收缩/转向/决策化）
- 对现实选择、行动方向、风险判断的影响
- 有纪念意义的表达

若只是临时信息或低价值闲聊，不进入正式档案。

### Step 2: 保存原始证据层

逐字或近似逐字对话 → `inbox/raw_transcripts/YYYY/YYYY-MM-DD_slug.md`
非逐字材料（文档摘录、整理稿） → `inbox/raw_extracts/YYYY/`，必须标明来源和记录方式

原始记录格式：
```markdown
# 对话记录：YYYY-MM-DD

## 来源
- 平台：
- 模型/对方：
- 记录方式：逐字转录 / 近似转录 / 整理摘录

## 用户原始问题

> [原句，不润色]

## 对话过程

### Q1: [用户问题原文]

[A: AI 回答摘要，标注为 "AI 分析/参考结论"]

### Q2: ...

## 用户的核心判断

- [用户明确表达的判断/立场]
```

### Step 3: 生成正式思想条目

按照 `schemas/dialogue_entry_template.md` 创建正式条目，放入 `entries/YYYY/MM/YYYY-MM-DD_slug.md`。

必须提取：
1. 原始问题（保留原句）
2. 用户的核心判断、猜想和推演
3. AI 分析/参考结论（标注身份，不混写成用户判断）
4. 新洞见、观点变化、反驳或修正
5. 对现实决策的影响
6. 相关旧观点
7. 后续值得追问的问题
8. 纪念意义（如有）

### Step 4: 判断是否更新观点卡

1. 先查 `ideas/idea_index.md`，再查 `ideas/idea_cards/`
2. 若相关观点已存在：优先合并、补充、标注变化（变化类型：强化/修正/反驳/扩展/收缩/转向/决策化）
3. 只有观点具备长期价值、反复出现或足够独立时，才创建新观点卡

### Step 5: 按需更新索引

只有在以下条件成立时才更新额外文件：
- 材料包含长期问题或问题状态变化 → `questions/question_index.md`
- 材料包含重要判断、隐含假设或可检验条件 → `claims/claim_index.md`（必须区分用户判断与 AI 分析）
- 出现明确转折、成长节点或现实决策 → `timelines/`、`decisions/` 或 `reviews/review_queue.md`

### Step 6: 输出处理摘要

说明：新增文件、更新文件、未处理事项、下一步建议。

## 观点变化类型

| 类型 | 含义 |
|------|------|
| 强化 | 新材料支持原观点 |
| 修正 | 原观点边界、条件或表达需调整 |
| 反驳 | 新材料明显挑战原观点 |
| 扩展 | 原观点可解释新领域/案例 |
| 收缩 | 原观点适用范围变窄 |
| 转向 | 思考方向发生明显变化 |
| 决策化 | 观点开始影响现实选择 |

## 观点状态尺度

- `seed` — 刚出现，尚未经过多次材料支撑
- `evolving` — 多次出现，正在成形或仍在修正
- `tested` — 已经过现实反馈、多个案例或阶段复盘检验
- `contested` — 存在强反例、内部冲突或重大不确定
- `retired` — 阶段性不再使用，但保留历史意义

## 完成标准

- [ ] 原始材料已保存或可追溯
- [ ] 正式条目已生成
- [ ] 已提取用户的原始问题和核心判断
- [ ] 已区分用户判断、用户猜想和 AI 分析/参考结论
- [ ] 已判断是否需要更新观点卡
- [ ] 必要时已更新问题总账和判断总账
- [ ] 已记录后续追问
- [ ] 没有制造明显重复文件
- [ ] 已输出简短改动总结
